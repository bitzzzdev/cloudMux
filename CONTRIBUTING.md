# Contributing

1. Keep Bash and Fish behavior aligned.
2. Do not add tokens, passwords, private keys, provider caches, or shell history to the repository.
3. Use the existing help table format when adding a command.
4. Test syntax with Bash and Fish before opening a change.
5. Explain user-visible behavior in `CHANGELOG.md`.

Open an issue for a bug or a missing provider workflow. Include the command name and a redacted error message.
